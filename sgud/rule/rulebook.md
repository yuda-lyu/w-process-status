# 規則帳本

本檔為套件設計與開發階段之規則帳本,為要求程式碼須長成什麼樣,或由規格產出之測試有哪些,包含軸、單一擁有者、已知限制、變更紀錄,以及對應之測試檔案或指令,由 agent 自行編列、擴充與維護.

## R-PS-LIST-01 清單欄位 exe、ppid、parentAlive,opt.timeout 與失敗原因 state(Gitea #55;2026-11-03 pr55)

- 依據: Gitea #55(使用端):全域設定 §8.6 之殘留 chrome 回收須判定「執行檔路徑」與「父行程已死」,使用端原用 wmic,Windows 11 已無 wmic 而靜默不動作.範疇: 底層為 psutil 之程序資訊(本套件 `src/WProcessStatus.mjs` JSDoc 首句:列出指定程序名稱的 pid 與狀態之清單);「是否自家 chrome、是否回收」之判定仍留使用端.
- 單一擁有者: 欄位值一律由 `srcPython/processStatus.py` 產生(`getExe`、`getPpid`、`getParentAlive`),JS 端不加工;`state` 之整理唯一在 `src/fmtState.mjs`(遮憑證用 wsemi `maskDiagText`,不另寫等價實作,診斷輸出與遮罩 D1);`opt.timeout` 之檢測唯一在 wsemi `execProcess`.
- 規則:
  1. 清單既有欄位(`name`、`pid`、`ram`、`username`、`status`)不變,新增 `exe`、`ppid`、`parentAlive`.`exe` 只對名稱相符者查(放入 `process_iter` 之 attrs 會對全部行程查路徑,每次多約 2 秒);空字串(System)或例外(無權限)為 `null`.`ppid` 取不到為 `null`.
  2. `parentAlive` 三態: `true` 存活;`false` 父行程已結束或其 pid 已被重用(ppid 所指行程不存在,或其建立時間晚於本行程;**建立時間相同視為存活**,同 psutil `Process.parent()` 之 `<=`);`null` 無法判定或本無父行程.**使用端只有 `false` 才當孤兒處置**,故下列一律 `null`、不得 `false`: ① ppid 為 `None`、0 或自身(System Idle Process、System;psutil 之 `parent()` 對最小 pid(Windows 之 0)固定回 `None`,若沿用 `parent() is not None` 則 Idle 為 `false`;System 之 ppid 為 0,其與 Idle 之建立時間同為 0.0,`parent()` 會回 Idle 而得 `true`,語意為杜撰,故亦 `null`);② 本行程建立時間取不到(AccessDenied、行程於查詢途中消失);③ 父行程建立時間因 NoSuchProcess 以外之例外(AccessDenied 等)無法取得.
  3. 不直接呼叫 `Process.parent()`: 其每次重做全系統行程快照(`ppid_map`,約 5 ms)並重查建立時間(合計約 9 ms/行程),94 個 `svchost.exe` 使查詢多約 0.77 秒.改為一次取 ppid 快照(`psutil._psplatform.ppid_map()`,psutil 內部函數,隨建置釘選之 psutil 版本;取不到時退回逐行程 `proc.ppid()`)、同一 ppid 之父行程建立時間只查一次;判定與 `parent()` 等價(兩輪各 264、262 個行程逐一比對 0 筆不一致,證據見 pr55 報告).升級 psutil 重建時須重跑該比對.
  4. `opt.timeout`: `WProcessStatus(name, opt)` 之 `opt` 非一般物件(含 `null`、讀取拋錯)視為未給;`opt.timeout` 原值轉傳 `execProcess`,由其依 dspec 輸入參數之檢測機制 K3 判定(非有效計時毫秒——0、負數、`Infinity`、非數字字串——視為不限時).逾時由 `execProcess` 以 `taskkill /T /F` 結束執行檔行程樹,reject 訊息開頭 `timeout[Nms]`.
  5. 失敗原因: 執行檔內部失敗時離開碼仍為 0、原因只印於 stdout,JS 端取 `execProcess` 之 resolve 值為 `state`,reject 訊息為 `output[...] is not an array, state[<整理後 state>]`.`state` 屬外來值(診斷輸出與遮罩 D3): 先取前 2000 字元,經 `maskDiagText` 遮憑證(網址帳密、`password=` 類鍵值對、Bearer;儲存路徑不遮,Q3),控制字元與換行換成空白,最多 200 個 code point(超過接 `...`),永不拋錯.本套件之執行檔輸出不含憑證(其錯誤原文僅 Python 例外訊息與 fpIn/fpOut 路徑),遮罩為防線.
  6. `readText`/`writeText` 以內建 `open(..., encoding='utf8', newline='')` 取代 `codecs.open`(`codecs.open` 自 Python 3.14 起棄用,該版建置之執行檔每次執行於 stderr 印 `DeprecationWarning`,混入 `state`;現行執行檔為 3.13 建置,無此警告,仍維持 `open` 以便日後升版不受影響);`newline=''` 保持原 `codecs.open` 不轉換換行之語意.
- 站點全集: `parentAlive` 回傳點 = `getParentAlive` 之 6 個 return(ppid 無父/本行程例外/父不存在/父例外/比較);`exe` 取得點 = `getExe` 1 處;`state` 進入訊息處 = `src/WProcessStatus.mjs` 1 處(經 `fmtState`).
- 盤點指令: Grep `srcPython/processStatus.py` 搜 `return` 於 `getParentAlive`;Grep `src/` 搜 `state\[` 與 `fmtState`(應各 1 處進入訊息);Grep `src/` 搜 `maskDiagText`(應僅 `fmtState.mjs`).
- 測試: `test/WProcessStatus.test.mjs`——子行程(`exe` 等於 `process.execPath`、`ppid` 等於本行程 pid、`parentAlive` 為 `true`;既有欄位集合不變)、孤兒(中介行程啟動孫行程後只結束中介行程,孫行程 `ppid` 仍為中介 pid、`parentAlive` 為 `false`;對照組存活時為 `true`)、`System` 與 `System Idle Process`(`exe` 為 `null`、`ppid` 為 0、`parentAlive` 為 `null`)、`opt.timeout`(`{ timeout: 1 }` reject 且 `timeout[1ms]` 開頭、逾時後以 `tasklist` 偵測無新增 `processStatus.exe`;夠長則正常;13 種未給或非預期之 opt 皆視為不限時而正常)、`state`(以攔截 `fs.writeFileSync` 令輸入 json 損壞或缺檔,由真執行檔自行失敗,驗訊息帶原因與 200 字元上限,路徑不遮)、`fmtState` 單元(上限、代理對不切、控制字元、遮憑證、非字串).等待一律為事件(子行程 stdout、exit)或偵測式輪詢(`waitUntil`),無固定延時當同步點.測試把 `TEMP`/`TMP` 導到 `test/_tmp/WProcessStatus/tmp`(PyInstaller 單檔執行檔被強制結束時其解壓夾 `_MEI*` 不會自清,隨夾具一併刪除).
